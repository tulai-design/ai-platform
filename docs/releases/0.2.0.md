# 0.2.0 — Anthropic Messages

Paired packages: `@tulai-design/agent-core@0.2.0` and
`@tulai-design/agent-providers@0.2.0`; providers depends on core `^0.2.0`.

## Changes

- Add `streamAnthropicMessages` and its public request, content and result types.
  Hosts keep their existing tool schemas and chat-shaped messages; the adapter
  creates native `system`, `tool_use` and grouped `tool_result` payloads.
- Retain native thinking blocks and signatures in `anthropicContent` for tool
  continuations. Streamed block indexes include text and thinking as well as tools.
- Support native adaptive effort on newer Claude models and thinking budgets on
  supported older versions. Leaving effort unset preserves service defaults.
- Require complete tool arguments and stream termination before exposing calls;
  cancellation, truncated JSON, error events and output limits cannot return
  executable partial calls. Requests are never automatically retried.
- Fix the shared HTTP boundary binding injected fetch to its options object.
- Keep existing Chat Completions and Responses APIs. An invalid Chat Completions
  stream that changes a tool's index is rejected rather than guessed together.
- No execution or approval behavior changes in agent-core; its version follows
  the repository's paired release policy.

## Consumer migration

Update both dependencies together. Choose Messages explicitly for native
Anthropic endpoints. For each tool round, pass the returned `anthropicContent`
unchanged on the next assistant message before adding tool results. Do not expose
opaque signatures as user-facing reasoning text. Protocol selection belongs to
the host; the provider does not retry a failed request using another protocol.

Default native output limit is 16,384 tokens; callers can set `maxOutputTokens`.
Provider credentials are supplied by the host and are not stored by this package.

## Release validation

The release gate includes a frozen install, build, production/test type checks,
deterministic protocol tests, package inventories and the isolated packed
consumer. The consumer compiles and runs the native Messages API through the
installed ESM export with no workspace aliases. Live paid provider calls are not
part of the gate.

Validated on 2026-10-27 with Node 24.11.0 and pnpm 9.12.0: frozen installation,
full `pnpm check`, 84 core tests, 61 provider tests (55 native Messages tests),
and the isolated packed consumer all passed. Both tarballs contain only emitted
JavaScript/declarations, package metadata, README and LICENSE. The release Git
tag identifies the reviewed source commit.
